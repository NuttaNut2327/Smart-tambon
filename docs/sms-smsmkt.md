# ส่ง SMS แจ้งลิงก์ให้ผู้แจ้งเหตุ (smsmkt)

ฟีเจอร์นี้ส่ง SMS ถึง "ผู้แจ้งเหตุ" ของแต่ละเรื่อง พร้อมลิงก์ไปหน้าติดตามสถานะเรื่องแบบสาธารณะ ต่อยอดจากระบบ SmartEMS เดิม
ใช้ผู้ให้บริการ **smsmkt** และ contract เดิม จึงใช้ credential ชุดเดียวกันได้ นอกจากนี้ยังมีเครื่องมือส่งและตรวจ OTP ด้วย

## ต้องขออะไรจาก smsmkt

ติดต่อ smsmkt (portal-otp.smsmkt.com) เพื่อขอข้อมูลต่อไปนี้

| สิ่งที่ต้องขอ | ใส่ที่ช่อง | หมายเหตุ |
|---|---|---|
| API key | `sms_api_key` | ระบบส่งค่านี้ในหัว `api_key` |
| Secret key | `sms_secret_key` | ระบบส่งค่านี้ในหัว `secret_key` |
| ชื่อผู้ส่ง (Sender name) ที่อนุมัติแล้ว | `sms_sender` | ไม่เกิน 11 ตัวอักษร ดูวิธีจดทะเบียนด้านล่าง |
| OTP project key | `OTP project_key` | ใช้เฉพาะ OTP ระบบเดิม hardcode ค่านี้ไว้ในซอร์ส ระบบใหม่ย้ายมาเป็นค่าตั้งค่าแล้ว |
| เครดิต SMS | — | ถ้าเครดิตหมด smsmkt จะตอบ code `400` |

ถ้า smsmkt ผูกสิทธิ์ใช้งานกับ IP ต้องแจ้ง IP ขาออกของเครื่องแม่ข่ายให้ smsmkt ด้วย ไม่อย่างนั้นจะได้ code `1007-4`

## จดทะเบียนชื่อผู้ส่ง (Sender name)

1. เลือกชื่อที่สื่อถึงหน่วยงาน เป็นภาษาอังกฤษหรือตัวเลข ไม่เกิน 11 ตัวอักษร เช่น `TambonX` หรือ `OBT-Pakklang`
2. ยื่นขอผ่าน smsmkt พร้อมเอกสารหน่วยงานตามที่ smsmkt และผู้ให้บริการเครือข่ายกำหนด เช่น หนังสือรับรองหรือหนังสือมอบอำนาจ
3. รอผลอนุมัติจากผู้ให้บริการเครือข่าย ระหว่างนี้ถ้าส่งด้วยชื่อที่ยังไม่อนุมัติจะได้ code `300` (ไม่พบชื่อผู้ส่ง) หรือ `1007-3`
4. เมื่ออนุมัติแล้ว ให้ใส่ชื่อนั้นในช่อง `sms_sender` ให้ตรงตัวอักษรทุกตัว

## ตั้งค่าในระบบ

เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ แล้วไปที่ **ตั้งค่าระบบ → SMS (smsmkt)** (`/sms_settings`)

| key | ความหมาย |
|---|---|
| `sms_api_key`, `sms_secret_key` | เข้ารหัสก่อนบันทึก และไม่แสดงกลับในหน้าเว็บ ถ้าเว้นว่าง ระบบจะใช้ `SMS_API_KEY` และ `SMS_SECRET_KEY` จาก `.env` |
| `sms_sender` | ชื่อผู้ส่งที่อนุมัติแล้ว |
| `sms_msg` | ข้อความโหมดติดตามสถานะ **ต้องมี** `<TRACKING-URL>` |
| `sms_video_msg` | ข้อความโหมดวิดีโอคอล (ปิดไว้เป็นค่าเริ่มต้น) |
| `host_url` | ที่อยู่เว็บสำหรับประกอบลิงก์ เช่น `https://tambon.example.go.th` ถ้าเว้นว่าง ระบบจะใช้ที่อยู่เว็บจากหน้าการแจ้งเตือนส่วนกลาง หรือ `APP_URL` |
| `OTP project_key` | ใช้กับ `/api/otp-send` ถ้าเว้นว่าง ระบบจะใช้ `SMS_OTP_PROJECT_KEY` จาก `.env` |
| กันกดส่งซ้ำ | จำนวนวินาทีที่ต้องรอก่อนส่ง SMS ซ้ำในเรื่องเดียวกัน (ค่าเริ่มต้น 60) |

ในข้อความใช้ตัวแปรเหล่านี้ได้: `{{organization_name}}`, `{{reference_code}}`, `{{title}}`, `{{system_name}}`

ตัวอย่างค่าเริ่มต้นของ `sms_msg`:

```
{{organization_name}} ได้รับเรื่อง {{reference_code}} แล้ว ติดตามสถานะได้ที่ <TRACKING-URL>
```

ในหน้าเดียวกันมีปุ่ม **ทดสอบส่ง SMS** และ **ทดสอบ OTP** ซึ่งใช้เครดิตจริง และมีประวัติการส่ง 20 รายการล่าสุด

## วิธีใช้งาน (เจ้าหน้าที่)

1. เปิดรายละเอียดเรื่องในหน้า **เหตุการณ์ทั่วไป** แล้วกดปุ่ม **ส่ง SMS** ใต้ข้อมูลผู้แจ้ง ปุ่มจะกดไม่ได้ถ้าเบอร์ของผู้แจ้งไม่ใช่มือถือ
2. เลือกโหมดการส่ง แล้วดูตัวอย่างข้อความกับลิงก์ที่จะส่ง
3. กด **ส่ง SMS** ผลจะแสดงในหน้าต่างเดิม ได้แก่ เบอร์ปลายทาง ลิงก์ที่ส่ง (คัดลอกหรือเปิดดูได้) และสถานะจากผู้ให้บริการ
4. ผู้แจ้งกดลิงก์แล้วจะเข้าหน้า `/t/<token>` ซึ่งแสดงเลขที่เรื่อง สถานะ ความคืบหน้า และช่องทางติดต่อ อบต. หน้านี้ไม่ต้องล็อกอิน และไม่แสดงชื่อหรือเบอร์ของผู้แจ้ง

## Contract กับ smsmkt

```
POST https://portal-otp.smsmkt.com/api/send-message
Headers: Accept / Content-Type: application/json, api_key, secret_key
Body: { "message": "...<TRACKING-URL>...", "sender": "...", "phone": "08xxxxxxxx", "url": "https://.../t/<token>" }
```

- smsmkt จะแทน `<TRACKING-URL>` ด้วยลิงก์ย่อของค่าใน `url` ยืนยันแล้วจาก [เอกสาร API ของ smsmkt](https://developers.smsmkt.com/en/api-reference) ถ้าส่ง `url` แต่ข้อความไม่มีแท็กนี้ จะได้ code `1003`
- **ส่งสำเร็จเมื่อ** HTTP status อยู่ในช่วง 2xx **และ** `code` เป็น `000` เพราะ smsmkt อาจตอบ HTTP 200 พร้อม code ข้อผิดพลาด
- OTP: `POST /api/otp-send` ส่ง `{project_key, phone, ref_code?}` แล้วได้ `result.token` และ `result.ref_code` กลับมา จากนั้นเรียก `POST /api/otp-validate` ด้วย `{token, otp_code, ref_code?}` แล้วได้ `result.status`

## API ของระบบ

```
GET   /send_sms?id=<incident_id>&mode=<tracking|video>&ajax=1   → ดูตัวอย่าง (ไม่ส่ง)
POST  /send_sms?id=<incident_id>&mode=<tracking|video>&ajax=1   → ส่งจริง
```

คำตอบ (`ajax=1`):

```json
{ "ok": true, "status": "200", "code": "000", "mode": "tracking", "phone": "0812345678",
  "link": "https://tambon.example.go.th/t/<token>", "template": "ข้อความที่ส่งจริง", "provider": { } }
```

- โหมดที่ไม่รู้จัก หรือโหมดวิดีโอที่ยังไม่ได้เปิด จะถูกเปลี่ยนเป็น `tracking` เสมอ ไม่ error
- ต่างจาก SmartEMS: **GET จะไม่ส่ง SMS** เพราะลิงก์หรือรูปภาพทั่วไปอาจถูกใช้สั่งส่งแทนผู้ใช้โดยไม่รู้ตัวจนเปลืองเครดิต การส่งจริงต้องใช้ POST พร้อม CSRF token
- ผู้ใช้ส่งได้เฉพาะเรื่องที่บัญชีตัวเองเห็นเท่านั้น

## สิ่งที่บันทึกทุกครั้งที่ส่ง

- **บนเรื่อง (`Incident`):** `sms_status` เป็น `SENT` หรือ `FAIL` ตามผลจริงจากผู้ให้บริการ พร้อม `sms_error` และ `sms_sent_at` ส่วน `tracking_token` สร้างครั้งแรกแล้วใช้ซ้ำ
- **ประวัติการดำเนินงานของเรื่อง:** บันทึก "ส่ง SMS ถึงผู้แจ้ง (โหมด…)" พร้อมผู้ส่งและเวลา
- **`SmsMessage` (audit):** เก็บข้อความที่ส่งจริง ลิงก์ เบอร์ ชื่อผู้ส่ง HTTP status, code และ response ของผู้ให้บริการ และผู้กดส่ง

## สิ่งที่แก้จากระบบเดิม

1. ระบบเดิมตั้งสถานะ `SENT` ทันทีโดยไม่ดูผล ระบบใหม่ตั้ง `SENT` หรือ `FAIL` ตามผลจริงและเก็บข้อผิดพลาดไว้
2. ระบบเดิมปิดการตรวจใบรับรอง TLS (`VERIFY_NONE`) ระบบใหม่ตรวจตามปกติ
3. ระบบเดิมไม่ normalize เบอร์ ระบบใหม่แปลง `+66`, `66`, ขีด และเว้นวรรค เป็นรูปแบบ `08xxxxxxxx` และรับเฉพาะมือถือ 06/08/09 ที่มี 10 หลัก
4. ระบบเดิมไม่มี timeout หรือกันกดซ้ำ ระบบใหม่ตั้ง timeout (เชื่อมต่อ 5 วินาที รอคำตอบ 15 วินาที) และลองเชื่อมต่อใหม่ 1 ครั้งเฉพาะกรณีที่เปิดการเชื่อมต่อไม่ได้ จึงไม่ส่งซ้ำ นอกจากนี้มีช่วงกันกดส่งซ้ำต่อเรื่อง
5. ระบบเดิมไม่เก็บ audit ระบบใหม่เก็บข้อความ ลิงก์ และ response ทุกครั้ง
6. ระบบเดิม hardcode `project_key` ของ OTP ไว้ในซอร์ส ระบบใหม่ย้ายมาเป็นค่าตั้งค่าที่เข้ารหัส

## โหมดวิดีโอคอล (เตรียมไว้ ยังไม่เปิด)

ระบบยังไม่มีห้องประชุมของตัวเอง ถ้ามีเซิร์ฟเวอร์ห้องประชุมแล้ว (เช่น Jitsi ของหน่วยงาน) ให้เปิดใช้ดังนี้

1. เปิด **โหมดวิดีโอคอล** แล้วใส่ URL ฐานของห้องประชุม
2. ระบบจะสร้างชื่อห้องต่อเรื่อง เก็บไว้ใน `Incident#video_room` แล้วใช้ซ้ำ ลิงก์ที่ส่งจะเป็น `<video_base_url>/<ชื่อห้อง>`
